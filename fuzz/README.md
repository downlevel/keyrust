# Fuzzing

[cargo-fuzz](https://rust-fuzz.github.io/book/cargo-fuzz.html) targets for code that parses
untrusted input. Requires a nightly toolchain:

```sh
rustup toolchain install nightly
cargo install cargo-fuzz --locked
cd fuzz
cargo +nightly fuzz run kdbx_header_peek -- -max_total_time=60
```

Seed corpora: `corpus/kdbx_header_peek/` holds copies of the KeePassXC test fixtures;
`corpus/vault_open_bytes/` holds small databases with minimal key derivation, generated by
`cargo test -p keyrust-core --features fuzzing --test fuzz_seeds -- --include-ignored`
(test data only), plus `kdbx31-header.kdbx`, the KeePassXC KDBX 3.1 fixture, so mutations also
reach the KDBX 3 header checks (`kdbx::header::kdbx3_transform_rounds`). Crashes are written to `artifacts/` (ignored by git). CI runs every target
for 60 seconds on each push; a long run is started by hand from *Actions → CI → Run workflow*
with `fuzz_seconds` (e.g. 1800).

| Target | Code under test |
|---|---|
| `kdbx_header_peek` | `keyrust_core::kdbx::header::peek`: KDBX4 outer header, no crypto |
| `vault_open_bytes` | `Vault::open_bytes_with_limits` on whole files, under `Limits::FUZZ` (resource limits, header, KDF, integrity checks, then keepass-rs parsing) |
| `vault_roundtrip` | arbitrary content → keepass-rs save → `Vault` open: XML writer/parser and decompression with extreme content (`keyrust_core::fuzzing`) |

**Coverage limits.**
- Random mutations of an encrypted file stop at the header hash and HMAC checks: everything after
  them (decompression, XML) is reachable only with the master key. `vault_roundtrip` exercises it
  with content keepass-rs itself writes; hostile raw XML is not fuzzed (keepass-rs 0.17 has no
  public XML parser), and a decompression size cap is to be requested upstream (see SECURITY.md).
- Found by `vault_roundtrip`: keepass-rs 0.17.0 reads a value made only of whitespace back as
  empty. Harmless in practice; to report upstream. The harness generates such values as empty.
